Bạn là senior full-stack engineer. Hãy refactor và mở rộng project Personal NAS hiện tại để hỗ trợ hệ thống “tools” có thể mở rộng về sau. Tool đầu tiên cần thêm là convert ảnh Sony RAW `.arw` sang `.jpg`.

Bối cảnh project hiện tại:
- Monorepo gồm:
  - `client`: Next.js 16 App Router, React 19, TypeScript, Tailwind/shadcn-style UI.
  - `server`: NestJS 11, TypeScript.
- App hiện có tính năng quản lý file cá nhân:
  - list/upload/download/delete/rename/create folder.
  - auth bằng JWT.
  - NAS root theo từng user qua `resolveInsideOwnerRoot(ownerFolder, relPath)`.
  - đã có `FilesController`, `FileService`.
  - đã có `ImagesController`, `ImageService`.
  - `ImageService` hiện đã nhận diện RAW như `.arw`, `.cr2`, `.nef`, `.dng`, `.raf`, `.orf`, `.rw2` để tạo thumbnail bằng cách extract embedded JPEG preview.
- Cần giữ nguyên cơ chế bảo mật path hiện tại: mọi input path phải resolve bên trong folder user, tuyệt đối không cho path traversal.

Mục tiêu chính:
1. Tái cấu trúc backend để có kiến trúc “tool system” mở rộng được.
2. Thêm tool đầu tiên: convert Sony `.arw` sang `.jpg`.
3. Thiết kế sao cho sau này có thể thêm raw profile của Canon/Nikon/Fuji/Panasonic/Olympus/DNG mà không cần viết lại toàn bộ pipeline.
4. Tích hợp UI cơ bản ở frontend để user có thể chọn file `.arw` trong NAS và convert sang JPG.

Tạo module mới:

Tạo cấu trúc tool registry:

Tool system cần support:
- list tools: `GET /api/tools`
- get tool detail: `GET /api/tools/:toolId`
- run tool: `POST /api/tools/:toolId/run`

Tool interface gợi ý:

```ts
export interface ToolDefinition {
  id: string;
  name: string;
  description: string;
  inputSchema: Record<string, unknown>;
  outputSchema: Record<string, unknown>;
  run(context: ToolRunContext, input: unknown): Promise<unknown>;
}

export interface ToolRunContext {
  ownerFolder: string;
}
```

Tool đầu tiên:

- id: `raw-to-jpg`
- name: `RAW to JPG Converter`
- version đầu tiên chỉ support Sony `.arw`.
- Input:
  - `sourcePath: string` - path file `.arw` trong NAS của user.
  - `outputDir?: string` - folder xuất JPG, mặc định cùng folder với file RAW.
  - `outputName?: string` - tên file JPG, mặc định cùng basename với source.
  - `quality?: number` - mặc định 92, min 1, max 100.
  - `overwrite?: boolean` - mặc định false.
  - `profileId?: string` - mặc định `sony-arw-default`.
- Output:
  - `success: boolean`
  - `sourcePath`
  - `outputPath`
  - `profileId`
  - `engine`
  - `metadata?`

Yêu cầu xử lý `.arw`:

- Backend cần validate:
  - sourcePath tồn tại.
  - extension là `.arw`.
  - file nằm trong owner root.
  - outputDir cũng nằm trong owner root.
  - không overwrite nếu `overwrite !== true`.
- Dùng `child_process.spawn` thay vì `exec`.
- Tạo service riêng:
  - `server/src/tools/raw/raw-to-jpg.tool.ts`
  - `server/src/tools/raw/raw-converter.service.ts`
  - `server/src/tools/raw/raw-metadata.service.ts`
- Primary engine: `darktable-cli`.
- Command export nên gọi dạng an toàn, ví dụ:
  - `darktable-cli <inputPath> <outputPath>`
- Không nối command bằng string.
- Nếu `darktable-cli` không tồn tại hoặc exit code != 0, trả error rõ ràng:
  - “darktable-cli is not installed or not available in PATH”
  - “RAW conversion failed: ...”
- Thêm env config:
  - `DARKTABLE_CLI_PATH`, default `"darktable-cli"`.
- Không cài darktable bằng npm. Chỉ document rằng host/server cần cài darktable system package.

Yêu cầu metadata:

- Nếu có thể, dùng package hiện tại `exifreader` để đọc metadata cơ bản.
- Nếu `exifreader` không đọc được RAW metadata thì không fail conversion; chỉ trả metadata rỗng hoặc partial.
- Metadata nên cố lấy:
  - make
  - model
  - lens
  - iso
  - aperture
  - shutterSpeed
  - focalLength
  - dateTimeOriginal

  - hiển thị toast/alert thành công.
  - refresh file list.
  - nếu có `outputPath`, cho nút “Open/Download JPG”.
- Tạo service frontend:
  - `client/src/services/tools-api.ts`
- Tạo types:
  - `client/src/types/tool.type.ts`
